# Flujo de trabajo — tuplus-tpl-001

- No se sube código funcional del sitio hasta que el prototipo de E3 esté aprobado (Puerta 2, EQU-03).
- Cada cambio va en una rama propia, nunca directo a `main`.
- Todo cambio se integra por Pull Request, revisado por otra persona antes de aprobarlo (revisión por pares, EQU-03 E4).
- Nombra las ramas por función: `feature/formulario-contacto`, `feature/hero`, etc.
- No se suben datos reales de clientes ni credenciales — solo contenido de ejemplo o ficticio.
